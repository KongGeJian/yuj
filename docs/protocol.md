# 链路协议契约（yuj-common 的对外契约）

> 本文是两端固件共同遵守的协议规范。任何改动必须双端同改并 bump `PROTOCOL_VERSION`，构建期断言。

## 一、总体：主从 TDMA ping-pong

**遥控器 = 主站**（掌控全局节拍），接收机 = 从站，只在被点名后的固定窗口内应答。无冲突、无 CSMA、时序确定。

```text
遥控器(TX)                          接收机(RX)
    │ ── 控制帧(摇杆/开关/指令) ──▶ │  t=0，收到 → 立即更新PWM输出
    │      (切信道/收发切换 ~130µs)  │
    │ ◀── 遥测帧(电压/状态/LQ/GPS)─ │  t≈0.5ms 固定窗口应答
    ▼ 4ms 后跳到跳频表下一信道，重复
```

| 参数 | 取值 | 理由 |
|---|---|---|
| 控制周期 | **4ms（250Hz）** | 数字舵机/电调体验流畅，F103 更新 8 路 PWM 无压力 |
| 空口速率 | **250kbps** | 同功率下距离比 1/2Mbps 远一倍，控制数据量用不了高带宽 |
| 可靠性 | nRF24 硬件 CRC + 应用层应答 | 双保险 |

## 二、帧格式

### 上行：控制帧（每帧必发，~19B）

| 字段 | 大小 | 说明 |
|---|---|---|
| type/flags | 1B | 4bit 帧类型 + 4bit 标志（低电告警等） |
| hop_count | 1B | 8bit 跳频计数，**失步自愈关键** |
| channels | 17B | **12ch × 11bit 压缩**（生效通道） |
| cmd | 0–6B | 指令（绑定/参数写入/failsafe 下发），type 区分 |
| — 预留 | — | **帧格式按 16ch 预留**（22B channels），未来 10–16 通道板零改动 |

### 下行：遥测帧（每帧应答，分类型轮播）

| 帧类型（2bit 类型字段） | 内容 | 频率 |
|---|---|---|
| 心跳 | 电池电压(2B, 0.01V) + 设备状态 flags + 上行 LQ(1B) + hop echo | 每帧，250Hz 冗余到不会丢 |
| GPS 片 | 片号 + 6B 数据 | 分片轮播，10Hz 刷新足够 |
| 串口透传片 | 片号 + 数据 | 轮播 |

## 三、跳频（FHSS）

| 项 | 设计 |
|---|---|
| 序列 | 伪随机信道序列，**种子在绑定时写入**，两端共享 |
| 对齐 | 帧头 8bit hop_count，接收机发现序号跳变即重新对齐（失步自愈） |
| 切换耗时 | nRF24 切信道 ~130µs，占 4ms 周期 3% |

## 四、信号质量：LQ（非 RSSI）

nRF24L01+ **无真正的 RSSI 寄存器**（仅 1bit "-64dBm 以上"标志），因此：

- **LQ = 1s 窗口内实收帧数 / 应收帧数**
- **双向独立统计**：遥控端测下行（屏显）、接收机测上行（放进心跳帧回传）

## 五、失控保护（Failsafe）

| 项 | 设计 |
|---|---|
| 触发 | 接收机 **500ms（可配）** 未收到有效帧 |
| 动作 | 所有通道输出预设安全值（油门最低/保持中位，**逐通道可配**） |
| 上电 | 未收到信号前**不输出** |
| 配置下发 | 遥控端按模型把 failsafe 配置**推送到接收机存储**（换模型重推），跟模型走、断电不丢 |

## 六、绑定与多机

| 项 | 设计 |
|---|---|
| 流程 | 遥控端菜单发起绑定 → 固定信道 + 固定地址广播 → 接收机**上电 5s 内按住绑定键** → 交换设备地址 + 跳频种子 → 各自存 Flash |
| 绑定表 | 遥控端存「模型 ↔ 接收机」绑定表，切模型自动对应对端，**一控多机** |
| 接收机硬件 | 专门绑定按键（PCB 已预留座子） |

## 七、版本纪律

| 规则 | 说明 |
|---|---|
| `PROTOCOL_VERSION` 宏 | 定义于 yuj-common，两端构建期断言一致，不一致编译失败 |
| 帧格式改动 | **必须双端同改** + bump 版本 |
| 只加不改的字段（预留位启用） | 允许小版本 bump |
| CI | 动 `yuj-common/` 的 PR 必须双端构建通过 |
