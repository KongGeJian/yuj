# 阶段一 PRD - PRD-stage-1.md

> 阶段一（基础遥控）需求单一真源，**所有设计/实现/验收围绕本文展开，防目标偏离**。需求变更先改本文。

## 1. 目标

**一句话**：做出一台能可靠遥控模型载具的整机——首版整机 PCB + 固件框架，链路、双主界面、模型管理、校准、全按键交互、震动+音频反馈全部可用。

| 项 | 内容 |
|---|---|
| 用户 | DIY 模型玩家（自己） |
| 硬件载体 | 遥控终端首版整机板（EDA 工程 `hw/yuj-core/`）；接收机不上整机板，F103 最小系统板+面包板联动验证 |
| 完成判定 | 遥控一台真车/真船跑起来，failsafe 实测可靠 |

## 2. 范围（In Scope）

### 2.1 链路（核心，风险最集中）

| 项 | 需求 | 备注 |
|---|---|---|
| TDMA 主从 | 遥控器主站，4ms（250Hz）控制帧 + 接收机固定窗口应答 |  |
| 跳频 FHSS | 伪随机序列，种子绑定时写入，hop_count 失步自愈 |  |
| 遥测 | 心跳（电压/状态/双向 LQ）每帧，GPS/串口片轮播 |  |
| Failsafe | 500ms（可配）触发，逐通道预设安全值，上电未收到信号不输出；**实机前必测** |  |
| 绑定 | 菜单发起→接收机上电 5s 内按绑定键；绑定表「模型↔接收机」一控多机 |  |

### 2.2 UI 与交互

参见 architecture.md §4

| 项 | 需求 | 备注 |
|---|---|---|
| 双主界面 | A 通道监视（默认）/ B 遥测仪表；View 长按切换 |  |
| 模型管理 | 完整版：模板→实例两级，通道设置/失控保护/输出模式随模型 |  |
| 系统设置 | 校准、绑定管理、显示设置、系统信息、恢复出厂 |  |
| 全按键交互 | 14 按键 + 4 拨杆 + View/Menu，交互三原则 |  |
| 反馈 | 震动（低电/失控提示）+ 音频提示 |  |

### 2.3 硬件

### 2.3.1 遥控终端 core

- 整机板：元件选型↔原理图↔PCB→gerber。因终端机原型搭建困难，直接成型，所以前三步要反复互相印证，最终结果影响 parts.md、pcb.md
- 外观：PCB 元件摆放服从外观布局定稿（core-外观布局.drawio）
- USB-C：兼顾供电/充电、通信。

### 2.3.2 接收机 rx

- 接收机原型：F103 最小系统板 + E01，面包板验证链路。

## 3. 不做（Out of Scope，防偏离红线）

| 项 | 归属 |
|---|---|
| USB 双模式（HID/CDC 上位机）、蓝牙手柄、游戏大厅、音效 | 阶段二 |
| 图传、手机 Wi-Fi 显示、天气/NTP | 阶段三 |
| 接收机整机板（含 LDO 选型） | 随接收机开发，阶段一仅面包板原型 |
| 霍尔摇杆、模拟扳机 L2/R2、ICM-42688-P、E01-2G4M27D | 后续优化（todo.md §2） |
| 图传集成进遥控终端主板、触摸屏 | 项目边界，不做（architecture.md §7） |

## 4. 验收标准

| # | 验收项 | 口径 |
|---|---|---|
| 1 | 链路 250Hz 稳定 | 整机板上长时间运行 LQ 不塌、无失步 |
| 2 | Failsafe 可靠 | 关遥控器 → 油门归预设，实机测试前必须先验证 |
| 3 | 绑定/多机 | 绑定流程可完成，切模型自动对端 |
| 4 | UI 完整 | 双主界面 + 模型管理 + 校准 + 全按键交互可用 |
| 5 | 反馈可用 | 震动 + 音频提示正常 |
| 6 | 整机可独立运行 | 电池供电、屏显电量条 + 低电报警（早于 BMS 6.0V 过放） |

> 软件能解决的不算问题；只有硬件架构级出入才返板（architecture.md §6）。
