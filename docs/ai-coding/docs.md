# 文档写作规范

## 原则

文档的读者是人（评审者/协作者/未来的自己），目标是**快速抓住决策与结论**，不是完整还原实现。

| 要求 | 说明 |
|---|---|
| **章节服务决策** | 每节只承载决策信息（背景/口径/改动/依赖/风险）；能从代码推导的实现细节不写 |
| **手段适配** | 对比/清单/依赖 → 表格化（加「状态/责任方」列）；并列要点 → 列表；层级 → 缩进；架构/流程 → 图；接口/配置/命令 → 代码片段。文字是最后手段 |
| **颜色/加粗凸显** | 触发条件、零改动、新增项、⚠ 待核对用加粗标出，其余保持克制 |
| **压缩合并** | 同主题小节合并；说明性长句砍短句 |
| **结构即摘要** | 开头一句话 + 表格让读者 10 秒抓住全貌 |
| **篇幅克制** | 每多一段话，注意力被稀释一分——极力克制 |

## 文档结构约定

| 位置 | 放什么 |
|---|---|
| 根 `README.md` | 对外项目介绍 |
| 根 `CLAUDE.md` | 统筹入口：概览 + 规范索引 |
| `docs/` | **跨模块**内容（架构/协议/选型/PCB/todo） |
| `yuj-x/docs/` | **模块独有**设计（硬件详设等） |
| `yuj-x/docs/ai-coding/law.md` | 模块增补规范（只写增补，不重复总规范） |

## 变更同步纪律

| 改动 | 必须同步 |
|---|---|
| 协议帧格式 | `docs/protocol.md` + 双端代码 + 版本 bump |
| 元件/模块选型 | `docs/parts.md` |
| PCB 设计决策 | `docs/pcb.md` 或模块文档 |
| 新增待办 | `docs/todo.md`（完成即勾掉，不删行） |
